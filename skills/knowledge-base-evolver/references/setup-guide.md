# 知识库最小骨架搭建指南

用户的知识库还没有索引体系时，先搭这套最小骨架再开始消化。

## 目录建议

```
知识库根目录/
├── 00_收件箱/            # 所有新东西先进这里，不直接落分类目录
├── 01_已整理/            # 按主题分类，目录不超过 2 层
│   ├── 主题A/
│   │   └── 主题A_MOC.md
│   └── 主题B/
│       └── 主题B_MOC.md
├── 90_归档/              # 过期但不想删的内容
└── 变更日志/             # 按月一个文件：YYYY-MM.md
```

原则：
- 收件箱是唯一入口，杜绝"直接存进分类目录"导致的查重失效
- 分类目录宁少勿多，主题目录超过 10 个就该合并层级
- 每个主题目录放一个同级 MOC 文件

## MOC 文件模板

```markdown
---
title: 主题A · MOC
type: moc
created: YYYY-MM-DD
updated: YYYY-MM-DD
---

# 主题A · 内容地图

## 子分类一
- [[文件名]] — 一句话说明这个文件是什么、什么时候查

## 子分类二
- [[文件名]] — 一句话说明
```

## 顶层索引（Wiki）模板

```markdown
---
title: Wiki · AI检索索引
type: index
updated: YYYY-MM-DD
---

# 检索索引

> 格式：`标签 | 路径`，标签为语义关键词。

- 标签1 标签2 | 01_已整理/主题A/文件名.md
- 标签3 | 01_已整理/主题B/文件名.md
```

用途：人和 AI 都通过它定位文件，标签写"会在什么意图下查它"。

## 文件 frontmatter 模板

```yaml
---
title: 标题
type: note            # note / project / moc / index
status: active        # active / paused / archived
created: YYYY-MM-DD
updated: YYYY-MM-DD
source: "来源：文章链接 / 口述 / 某次学习"
tags:
  - 主题标签
---
```

## 变更日志模板

```markdown
## YYYY-MM-DD HH:mm

- 动作类型：归档
- 摘要：消化收件箱 5 篇，合并 2 篇进主题A
- 影响文件：[[文件1]] [[文件2]]
- 后续确认：无
```

## 首次接入存量文件

存量文件多时不要一次性全整理：
1. 先搭骨架 + 建各主题 MOC
2. 每次消化一批（≤20 个），按六步流程走
3. 优先消化收件箱，存量归档放后面
