# 小海豚 IP 生成

把一句自然语言需求，变成可以直接交给图像模型或设计师使用的 IP 方案。

## 什么时候用

- 用户要设计小海豚校园宠物形象
- 用户要把一段文字转成卡通 IP prompt
- 用户要头像、立绘、贴纸、主页卡片、活动海报的统一风格
- 用户给了参考图，但需要抽成可复用的风格规则

## 默认前提

- 默认项目是小海豚 AI 校园宠物
- 默认角色是海豚系校园宠物
- 默认气质：友好、轻社交、清爽、聪明但不装
- 默认不做官方校徽感，不做人脸拟真，不做过度幼态
- 默认强调“自然语言 -> 角色设定 -> 生成提示词”的链路

## 先读这些参考

- `references/brief-fields.md`：输入字段和默认补问顺序
- `references/style-map.md`：小海豚项目的风格映射和默认配色
- `references/prompt-template.md`：可直接复用的 prompt 骨架
- `references/negative-rules.md`：必须避免的视觉和语义误区
- `references/qa-checklist.md`：交付前的快速检查表

## 工作流

### 1. 先拆需求

把用户描述拆成 5 个部分：

- 角色是谁
- 性格是什么
- 校园语境是什么
- 视觉锚点是什么
- 用在什么场景

如果信息不全，优先按 `brief-fields.md` 的默认顺序补齐。

### 2. 再定角色骨架

输出一版简短角色骨架：

- 名称
- 定位
- 性格
- 视觉关键词
- 主色
- 配件
- 适用场景

角色骨架要稳定，后续所有 prompt 都从这里派生，不要每次重写一套人格。

### 3. 产出风格映射

把自然语言翻成可执行的视觉约束：

- 轮廓是圆润还是利落
- 表情是软萌还是冷静
- 配色是清爽海洋系还是更活泼的校园系
- 细节是偏少还是偏多
- 画面是头像、立绘、贴纸还是主页卡片

### 4. 生成 Prompt

默认给出三段内容：

1. 主 prompt
2. negative prompt
3. 可选变体

主 prompt 先讲主体和风格，再讲比例、场景、材质、光感和输出用途。
negative prompt 先压掉：拟真、官方校徽感、过度幼态、杂乱背景、错误文字、表情包化。

### 5. 给出参考图策略

如果用户给了文字但没给图，就说明应该找什么参考图。
如果用户给了参考图，就说明参考图该抽哪些维度：

- 轮廓
- 配色
- 情绪
- 配件
- 质感

不要把参考图当成照抄对象，只把它当作风格信号。

## 输出顺序

默认按这个顺序输出：

1. 角色设定卡
2. 风格映射
3. 生成 Prompt
4. 负面约束
5. 参考图策略
6. 可选变体

## 口径约束

- 不要把小海豚写成官方学校吉祥物
- 不要把真实学生照片当角色原型
- 不要把人脸细节做成拟真肖像
- 不要把画面做得太满
- 不要让说明文字替代视觉规则
- 不要让同一个项目里每次都换完全不同的视觉逻辑

## 默认成功标准

一版好的输出，应该让人能直接拿去画图，且下一次还能复用同样的骨架，只改少量关键词。
