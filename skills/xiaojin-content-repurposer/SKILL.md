# 多平台内容改写

## 入口

1. 先按知识库根 AGENTS 和目标项目规则启动。目标默认是 `05-项目/个人内容创作中心`，库根由当前工作区确认，不硬编码本机路径。
2. 查内容总卡、母稿、现有平台稿、发布记录及复盘；查重后才写。
3. queued 只保存。用户明确选中具体主题或直接要求写它，才可推进；不批量把待选池当授权。已有 published 内容派生新稿时保留原发布事实。
4. 本技能只在 Agent 中执行文本工作流，无自动后台任务，不负责同步电脑、登录账号或发布。

## 工作流

1. 从母稿提取内容核心包，写入母稿：核心观点、目标读者、真实案例、来源证据、可复用步骤、能力边界。新增核实的事实先回到母稿，再派生；有冲突先澄清。
2. 读 [平台适配](references/platforms.md)；只生成用户指定渠道，未指定且要求全平台时生成五个平台。X 默认 Article 长文，不能擅自拆 Thread。
3. 每个平台重建标题、开头、结构、配图用途和一个收尾动作；统一保持作者朴素的实操语气，不强加“姐妹们”“99%的人不知道”等模板。长度取决于任务完整度，平台硬限制发布时查官方规则。
4. 使用项目现有模板。各平台稿沿用同一 content_id，填写 source_mother、source_card、source_version、channel、format、version 和 stage。母稿改动后将受影响渠道标为需复核，不能无依据声称同步完成。
5. 按 [审核清单](references/review.md)检查，输出“通过/缺证据/待人工检查”及具体证据，不生成伪精确质量分。新稿默认 review；未做配图/录屏就写 planned。
6. 如果用户提供的工作区已有内容总卡、MOC、Wiki 或变更日志，按其规则回链并更新；不要为一次性草稿创建新的索引体系。全局 published 不代表新渠道已发布。已发布正文不可覆盖，新 X 改写稿明确是再版草稿。

## 事实与素材

- 数字、个人经历、效果、引文必须能定位来源。没有就删掉该断言或列为待补，不能为吸引力补写。
- 模板/重建提示词必须注明用途与未验证状态，不冒充原发布附件；演示数据显著标为“演示”，不能当真实工作结果。
- 不把 Page 展示交互写成数据回写，不把建议写成实现，不把旧链接写成当前可访问。
- 图片先读知识库生图技巧；真实界面用脱敏截图，不绘制假截图当证据。本文技能负责配图方案，不宣称图已生成。
- 外发正文不出现内部绝对路径、任务库私密内容、Token、手机号或未授权第三方材料。技术教程必须讲清权限和能力前提。
- 不上传母稿、不发送他人消息、不安排发布，除非用户明确要求该动作。授权改写不等于授权发布。

## 来源

本版本为本地适配，参考 qianjin-content-repurposer 的内容解构与平台重构流程，以及 platform-content 的缺口与跨稿事实追踪思路；补充 X Article、飞书、知识库状态门槛及证据边界。来源及许可证见 [来源](references/sources.md)。不采用上游未经验证的增长百分比、算法断言或固定人设。
